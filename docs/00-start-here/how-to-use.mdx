<TLDR>
Each chapter is short (3 to 5 minutes), has the same sections, and uses one example app called TaskFlow.
Start with the TaskFlow reference, then read by part or use the playbooks when you have a specific problem.
</TLDR>

## Reading paths

| If you are... | Start with |
|---|---|
| New to testing | Part 1 → Part 2 → Part 3 |
| Writing API or UI tests | Part 4 → Part 5 → playbook 45 |
| Owning performance or load testing | Part 9 → Part 10 → Part 11 → Part 12 |
| Looking at AI tools for testing | Part 13 and the tool directory |
| Looking for a checklist | Part 8 (playbooks) |

## What every chapter has

1. **TL;DR**: the short version.
2. **What and why**
3. **How it works**: a diagram where it helps.
4. **When to use it, and when not to**
5. **TaskFlow example**
6. **Do this** and **Avoid this**
7. **Further reading**: only verified links.

## Rules this handbook follows

- Plain English, short sentences.
- One topic lives in one chapter. Other chapters link to it.
- Facts about tools and companies carry an **as of** date. If we could not check a fact, we left it out.
- Load and performance results are **Illustrative data** unless a page says otherwise. Nothing here was measured on a real AWS account.
- Recommendations are labelled as recommendations, not as standards.

## Find things fast

Use search (top bar), or go to [Find what you need](/start-here/find-by-problem) and pick the job you have. The [glossary](/start-here/glossary) explains terms used across chapters. Copy-paste documents (bug report, test plan and more) are under **Templates** in the sidebar.
