## What and why

The bug switch turns on one bug at a time with the environment variable `TASKFLOW_BUGS`. Each ID makes the app in `examples/taskflow/app/main.py` do one wrong thing. Use this page to check your own results, not to skip the work.

## How to reproduce

Run these commands from `examples/taskflow`:

```bash
cd examples/taskflow
TASKFLOW_BUGS=B01 pytest tests -q
```

Replace `B01` with any ID from B01 to B08. Leave the variable unset to run the bug-free app. With no bug on, all 59 tests in `tests` pass.

| B04 | Assign without member check. Assigning a non-member gets 200. | API test of the assignment rule | `TASKFLOW_BUGS=B04 pytest tests -q` | `tests/test_taskflow_api.py::test_only_project_members_can_be_assigned` (1 failed) |

The counts are from running each command above. They match the output of `examples/taskflow/bug-hunt/verify_bugs_detectable.py`, which checks that every ID fails at least one test.

## Tests outside `tests`

The full suite, `pytest tests unit bdd doubles -q`, catches more. The bug-hunt `SPOILERS.md` file lists these extra failing tests:

- B01: `unit/test_status_rules.py::test_title_length_rule[101-False]`
- B04: `bdd/test_assign_task.py::test_assign_a_task_to_someone_who_is_not_a_member_of_the_project`
- B08: `unit/test_status_rules.py::test_invalid_priority_is_rejected`

Each of these was run with the matching `TASKFLOW_BUGS` value on 2026-11-06 and failed as listed. The B08 unit test fails for three values (`URGENT`, `low` and an empty string). For a live check with curl, the steps and expected status codes are in `examples/taskflow/bug-hunt/SPOILERS.md`.

Bug B01 behaves as described on the default SQLite setup. With Postgres (`docker compose up`), the database column limit would reject a 101-character title with a server error instead of accepting it.
