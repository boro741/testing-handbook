8. Bottleneck analysis

Hypothesis: task CPU limits throughput

Evidence: Average task CPU peaked at 38% while p95 was 480 ms.

Conclusion: Rejected. CPU has room left.

Hypothesis: Database connection pool is exhausted

Evidence: DB connections sat at 100 of 100 for about 8 minutes. Pool wait p95 was 310 ms. Previous run peaked at 62 connections.

Conclusion: Confirmed as the main cause. Release 2.4.0 raised the pool from 10 to 20 per task.

Hypothesis: Downstream slowness on the ALB path

Evidence: Target response time p95 was 470 ms, which matches the app-side p95. ALB 5XX from ELB was 5, so the load balancer is not the cause.

Conclusion: Not the main cause.

10. Risks, limitations and what was NOT tested

Risks and limitations

  • Only one task size and one task count were tested.
  • Peak traffic mix came from one month of access logs; real peaks may differ.
  • The load generator ran on one machine. Its own limits were not checked.

Not tested

  • Stress test above 450 RPS
  • Soak test (for memory growth over hours)
  • Failover of an RDS instance
  • Other services (auth-service, project-service, notification-service)
